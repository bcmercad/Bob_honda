Learning outcomes

The academy is designed for customer engineers who are new to Bob and need a practical path from orientation to governed team adoption.

01

Understand Bob

Explain Bob’s role, core capabilities, human-control model, and place across the software-delivery lifecycle.

Exit evidence:Can identify appropriate Bob use cases and boundaries.
02

Begin using Bob

Set up Bob, initialize repository context, select the right mode, and complete a safe first engineering task.

Exit evidence:Completes one reviewed task in a non-production repository.
03

Become productive

Use Bob for understanding, planning, coding, testing, documentation, review, and modernization work.

Exit evidence:Applies Bob repeatedly in a daily engineering workflow.
04

Standardize team usage

Turn successful practices into shared context, rules, modes, skills, templates, and approval checkpoints.

Exit evidence:Publishes at least one reusable team asset.
05

Prepare for enterprise rollout

Apply security, access, governance, measurement, support, and adoption practices required to scale responsibly.

Exit evidence:Contributes to a documented team or enterprise rollout plan.

Choose a role-based route

The academy is primarily for customer engineers starting with Bob. Role views provide a faster route to relevant capabilities and use cases without replacing the core beginner-to-advanced sequence.

Build, test, review, and modernize applications

Focus on project context, effective engineering tasks, code generation, testing, reviews, reusable skills, AI integration, and safe human approval.

  • Complete stages 1–5 of the guided path.
  • Start with Getting Started with Skills, Using Java with Skills, and Quarkus AI Integration.
  • Progress to architecture testing and application-modernization tutorials.

Understand and modernize complex legacy systems

Focus on code understanding, architecture recovery, knowledge transfer, modernization planning, automated validation, and exposing existing capabilities through modern interfaces.

  • Prioritize Automated Architecture Tests, Modernize EJB to Quarkus, Legacy to MCP, and Grounded Docs.
  • Use Bob to document dependencies, business logic, risks, and modernization options before changing code.
  • The public demo repository currently emphasizes legacy Java patterns rather than a z/OS-specific tutorial; apply the same learning pattern to IBM Z workloads with appropriate tools and controls.

Turn business context into structured engineering inputs

Focus on understanding existing systems, organizing requirements and acceptance criteria, grounding Bob with internal documentation, and improving handoffs among business, product, design, and engineering teams.

  • Start with Grounded Docs, Bob Modes, and the AI-first product-development video.
  • Use Bob to create process summaries, user stories, acceptance criteria, design questions, and traceable handoff artifacts.
  • The current GitHub repository is engineering-heavy, so these tutorials are adjacent patterns rather than dedicated BA or design exercises.

Standardize architecture, delivery, and platform workflows

Focus on AGENTS.md, custom modes, rules, skills, CI/CD generation, architecture tests, MCP integrations, security boundaries, and reusable platform patterns.

  • Prioritize Ansible DevOps, Tekton DevOps, Automated Architecture Tests, Bob Modes, and Legacy to MCP.
  • Turn approved standards into version-controlled Bob context and reusable skills.
  • Define permissions, security controls, and validation checkpoints before scaling.

Scale adoption around measurable engineering outcomes

Use the learning hub as a curriculum and connect enablement to productivity, modernization, quality, rework, governance, and adoption metrics.

  • Review the overview videos and the full GitHub demo catalogue.
  • Select a small set of role-relevant tutorials for onboarding and champion programs.
  • Measure cycle time, quality, rework, review effort, modernization throughput, and active adoption—not prompt volume.

Prepare for client enterprise rollout

The final objective is not only individual proficiency. Customer engineering teams should be ready to scale Bob with explicit access, standards, support, governance, and measurable outcomes.

Review security guidance ↗
Define approved users, repositories, data classes, models, and MCP servers.
Document human approval points for code changes, external actions, and production delivery.
Version-control AGENTS.md, rules, modes, skills, templates, and ownership information.
Establish onboarding, champion support, escalation, and content-review processes.
Measure active adoption, cycle time, quality, rework, review effort, and modernization throughput.
